#+language: pt_BR
#+options: toc:2 num:nil

* Visão geral

O script =run_all.sh= coordena a preparação dos dados e a execução de vários
modelos. O fluxo geral é:

1. baixar os dados brutos, salvo quando =RAW_DIR= é fornecido;
2. construir o corpus processado;
3. gerar características BoW;
4. gerar embeddings;
5. executar os modelos para cada seed;
6. agregar resultados após cada seed.

* Configuração padrão observada

| Parâmetro | Padrão |
|-----------+--------|
| =ROOT= | =data/ogbn= |
| =EMB= | =minilm= |
| =K= | =50= |
| =SEEDS= | =0 1 2 3 4= |
| =TEXT_MODE= | =full= |
| =NBR_K= | =10= |
| =min-df= | =20= |
| =max-df= | =0.3= |
| =max-features= | =5000= |

A lista padrão de modelos do shell inclui =lda=, =nmf=, =prodlda=, =ctm=,
=ctm_knn=, =ctm_cite= e =ctm_both=. O executor individual também reconhece
outras variantes.

* Etapas

** Preparação

O pipeline chama aquisição, corpus, características textuais e embeddings nessa
ordem. A construção de BoW usa parâmetros explícitos no shell: mínimo de
documentos 20, máximo 30% e até 5.000 atributos.

** Experimentos por seed

Para cada seed, =run_experiment.py= carrega o =Bundle=, verifica a presença dos
artefatos necessários ao modelo, executa treinamento e avaliação e grava um JSON
sob:

#+begin_example
<root>/results/<emb>/<corpus-fingerprint>/<model>_K<K>[_tag]_s<seed>.json
#+end_example

Resultados existentes são ignorados, a menos que =--force= seja usado.
Parâmetros neurais adicionais podem ser configurados pela CLI, incluindo
dimensão oculta, dropout, taxa de aprendizado, batch size, épocas e peso/
annealing do KL. =--save-theta= solicita a persistência das distribuições
documento-tópico.

** Agregação

O shell tenta agregar resultados depois de cada seed. A chamada de agregação é
tolerada com =|| true=, portanto uma falha nessa etapa não necessariamente
interrompe o restante do pipeline.

* Implicações operacionais

- O uso de =set -euo pipefail= torna erros não tolerados nas etapas principais
  capazes de interromper o script.
- A agregação tolerada pode ocultar falhas; os logs devem ser inspecionados.
- A existência de um JSON de resultado pode fazer o executor pular uma
  repetição, mesmo que a configuração atual tenha mudado. Use nomes/tags
  distintos ou =--force= quando necessário.
- Os artefatos BoW e embeddings devem corresponder ao corpus carregado.
